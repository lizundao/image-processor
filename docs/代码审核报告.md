## 一、审核结论摘要

项目整体架构清晰：React 前端负责图片导入/参数配置，Rust 后端（`image`/`imageproc`/`webp`/`gif` 等）负责实际像素处理，全离线、无网络请求。前端 `npm run build` 通过。但存在**多处会导致应用直接崩溃（panic=abort）的边界缺陷**、**放宽的桌面安全配置**与**文案合规风险**，逐项如下。

## 二、崩溃类缺陷（P0，最优先）

Rust Release profile 设置了 `panic = "abort"`，任何 panic 都会**立即终止整个进程**（无错误提示、直接闪退），因此输入边界必须全部兜住。

| # | 位置 | 问题 | 触发条件 | 修复 |
|---|---|---|---|---|
| 1 | `services/gif.rs:98` | `1000 / settings.fps` 整数除零 → panic | fps=0（前端默认 10，但 IPC 可被构造 0） | 先校验 fps∈[1,30]，非法返回 Err |
| 2 | `services/grid_slice.rs:73-74` | `width / columns`、`height / rows` 除零 | rows 或 columns=0 | 入口校验 rows/columns ≥1 且有限 |
| 3 | `services/merge.rs:100,109` | `panic!("没有图片需要合并")` / `panic!("不支持的合并方向")` | 非法 direction 或空列表直达 | 改返回 `Err`，移除 panic |
| 4 | `utils.rs:149-151`、`services/border.rs:276-278` | `&hex[0..2]` 按**字节**切片；若颜色串含多字节字符（如中文）会切在 UTF-8 字符中间 → panic | 用户/输入传入非 ASCII 颜色串 | 先做 ASCII 校验 + 长度校验再切片 |
| 5 | `services/crop.rs:212,219` | `img_height as f32 * target_ratio` 当 ratio 为 0/负/NaN/inf 时结果为 0/溢出，`crop_imm` 越界 | aspect_ratio=0 或异常 | 校验 ratio 为有限正数；裁剪尺寸 clamp |
| 6 | `services/border.rs:168,228,243,629` | `width + border*2`、`height - border_width`、`width - border_width*2` 在 border 过大或图片过小时 u32 溢出/下溢 | 边框宽度 > 图片尺寸 | 边框宽度 clamp 到图片可容纳范围，用 checked 运算 |
| 7 | `services/gif.rs:92,103` | `first_dimensions as u16` 当宽或高 > 65535 时截断为 0 → GIF 编码器错误 | 超大尺寸图片 | 缩放前校验并拒绝/缩放超大尺寸 |
| 8 | `services/merge.rs:127,181` | `spacing * (len-1)` 及累加可能在极端值下溢出 | 超大间距/超多图 | checked 运算 + 上限保护 |

## 四、资源与健壮性（P1）

- `services/enhance.rs`：`enhance_preview` 临时文件写在 `current_exe()` 同目录 `temp/`，安装版（Program Files）可能无写权限 → 应改用应用数据目录；`cleanup_preview_temp_files` 同步调整。
- 前端 `tauriImageProcessing.ts`：临时文件清理仅在成功路径 `await cleanupTempFiles`，异常分支泄漏；应 `try/finally`。
- `services/convert.rs::count_unique_colors`：对超大图构建 `HashSet`，内存与耗时可能失控 → 采样或上限保护。
- 批量处理语义不统一：compress/convert/grid_slice 任一失败即返回空 `processed_files`（丢弃已成功文件），crop/merge/border/rotate 保留部分成功 → 统一为「保留已成功 + 汇总错误」。
